# Live basketball implementation and access boundary

Checked October 23, 2026. The user has **no licensed basketball provider access**. No account, subscription, credential, paid request, live room registration or deployment was created. ## Provider coverage and uncertainty

The implemented candidate is **Sportradar NBA v8 REST JSON**, with a daily-schedule discovery request and full game play-by-play snapshots. It is tested with synthetic vendor-shaped fixtures only. WNBA, college basketball, G League weighted free throws, Push streaming and continuous tracking are not implemented by this adapter.

Official references checked:

- [NBA play-by-play](https://developer.sportradar.com/basketball/reference/nba-play-by-play): event IDs, update timestamps, statistics, explicit post-event team possession and ordering.
- [NBA live game guide](https://developer.sportradar.com/basketball/docs/nba-ig-live-game-retrieval): JSON statistics examples and schedule/snapshot retrieval. The guide and endpoint reference give different cache TTLs; neither proves occurrence-to-client latency or a safe call window. Push reconnection statements also differ across documentation versions, so this implementation makes no Push resume guarantee.
- [Authentication](https://developer.sportradar.com/getting-started/docs/authentication): server-side `x-api-key` header over HTTPS.

`wall_clock` records statistician entry time, not independently verified action occurrence. The adapter preserves it in the internal timestamp field, but declares `timestampPrecisionMs:null`. Consumers **must** honor that capability; this feed cannot open wall-time or next-action calls until occurrence semantics and uncertainty are established. Source heartbeat is not a historical completeness watermark.

Supported player credits are made two/three-point field goals, free throws, rebounds, assists, steals, blocks and turnovers. Missed shots become attempts. Team-only rebound/turnover statistics do not manufacture player credits. Explicit `possession` supplies the team after an event; a scorer, assist provider or on-court player is never treated as the ball holder. Event locations are not continuous tracking observations. Unknown statistics and invalid clocks/entities reject ingestion. Unsupported removals/structural changes close ingestion for operator reconciliation rather than silently leaving a stale score.

Only `status:closed` produces a final marker. `complete` is provisional and cannot settle a final result through this adapter. Licensed samples must validate lifecycle and correction behavior before activation.

Coverage entitlement, quotas, storage/retention permission, redistribution, product costs and event timestamp quality remain unverified for an account. Score/stat licensing grants no broadcast-video rights.

## Implemented service APIs

- `SportradarBasketballProvider(options)` implements `discover`, `snapshot` and `poll`; fetch and clock are injectable. Requests have cancellation and timeout, no credential in URL, redacted HTTP errors, a bounded response body (default 8 MiB), and no redirect credential forwarding. Poll retrieves an authoritative full snapshot; its SHA-256 cursor identifies content, not a vendor stream-resume token.
- `normalizeProviderEvent` maps explicit vendor identities through the supplied catalog. Optional `rawPayloadRef` retains a SHA-256 digest of the originating vendor event outside reducer fields. This is a content reference, not a retained raw-payload archive; authorized retention/storage must be configured separately.
- `reconcileJournal(previous, batch, catalog)` returns `{journal,state}`. `journal.entries` retains accepted event revisions; `journal.events` contains ordered authoritative `BasketballEvent[]`; `journal.resultVersion` identifies the latest projection inputs. Exact duplicates do not add entries. Revisions replace earlier inputs before replay through the existing pure reducer, so a corrected two becomes three points, not five. Conflicting equal revisions, aliased identities, chronology errors and normalized sequence gaps reject the entire batch. Local receive-time changes do not create a new outcome version. A changed vendor update timestamp is required for a changed event payload. Brief batch reordering is supported; missing sequences fail closed rather than guessing a missing event.
- `ingestProviderBatch(options)` loads a durable checkpoint, normalizes/reconciles snapshot or poll data, saves the complete next checkpoint, then publishes. Failed save never publishes. Authoritative snapshots missing previously accepted identities require explicit reconciliation. Reads do not call the provider. A publish failure cannot undo saved authority; clients recover from cached snapshots.
- `runBasketballProvider(options)` owns polling, cancellation and bounded exponential retry. HTTP 429/5xx and transport failures retry; authentication, validation and persistence failures stop. `Retry-After` is honored; a delay above the configured bound stops for operator attention instead of retrying too early. `onUnavailable` must close runtime source gates immediately. The default poll interval is a proposed 3 seconds, not measured latency or a verified account quota.
- `JsonProviderCheckpointStore(path,catalog)` validates and reconstructs authority after restart. Save writes a same-directory temporary file, fsyncs it, closes it and atomically renames it before returning. Missing initial file is allowed; corrupt checkpoints fail closed. The parent directory must exist. Run one writer per checkpoint. This is local single-process storage, not a multi-host lease or a proven power-loss-safe deployment; platform directory-entry persistence and backup/restore need deployment validation.
- `resolveTeamScoringWindow(target,events,health)` resolves real-time half-open `[startsAt,endsAt)` windows only after a trustworthy coverage watermark. Acceptance closes before the outcome interval with a declared guard. Unknown precision, boundary uncertainty, source gaps and discovered actions predating acceptance void the target; game-clock stoppages never extend it. It is a pure resolver foundation, not an enabled room template. The present adapter's null precision keeps this unavailable.
- `normalizeTrackingPoint(observation,geometry,now,maxAgeMs)` maps real observations to `[0,1]`, with explicit orientation and timestamp/confidence/source. Unknown court side, dead balls, bounds errors, stale points and missing observations return unknown. No interpolated or continuous path is invented. Runtime tracking remains unavailable without an entitled repeated-observation feed.

## Offline position-calibration evaluator

`server/src/live/basketball/calibration.ts` exports pure `evaluateCalibration(input)`. This is separate from the existing authored-demo calibration report and never changes global catalogs, salaries or room rules.

Inputs declare dataset identity/authorization, source kind, chronological half-open training and later held-out windows, a minimum sample count per position in each split, player-game statistics with observed minutes and availability timestamps, pregame projections, and current/candidate catalog and rules versions. Training uses only observations available by the training cutoff; later held-out values cannot change learned weights. Unknown positions, empty/unsupported/noninteger/negative counters, invalid timestamps and invalid minutes are excluded. Sparse known stat counters imply zero omitted credits. Minutes must be observed, finite and within `(0,120]`; this declared sanity bound excludes extreme inputs rather than imputing playing time. Evaluation uses raw **per-game totals**, with no per-minute normalization or invented minutes. Reports include counts and total observed minutes for each split/position. Duplicate player-game rows are excluded and fail validation so a duplicated dataset cannot inflate evidence.

Training proposals use the observed league mean divided by each position mean, clamped to `[0.80,1.25]`. All five positions require sufficient positive training production and the declared sample threshold. The later held-out weighted mean for each position must be within 10% of the held-out league raw-production mean. Candidate pregame projections are reweighted and repriced under the existing declared demo salary policy (350 points-to-salary rate, 3,500–11,500 salary bounds, 500-unit rounding). At least three different captains must each admit a legal captain-plus-four lineup under the 50,000 cap and 1.5x captain salary. The evaluator reports these candidate salaries and the count; it does not adopt them.

Failed or insufficient validation returns neutral effective weights. Synthetic datasets also always retain neutral effective weights and cannot authorize adoption. A successful proposal additionally requires caller-declared authorized historical provenance and distinct nonempty candidate **catalog and rules versions** before `adoptionEligible` becomes true. This flag is an offline proposal for review, not independent rights verification or an automatic migration. Existing rooms remain unchanged; adoption would apply only through separately versioned future room catalogs. Role, minutes and dataset-selection differences remain explicit limitations.

Observed: `npx vitest run server/test/live/basketball-calibration.test.ts --maxWorkers=1` passed **6 synthetic tests**; `npx tsc --noEmit -p server/tsconfig.json` passed. No authorized historical dataset was supplied or evaluated. Real-world positional balance remains unverified and runtime weights stay neutral.
