# Gemini development provider

The user approved Gemini for development, retaining Bedrock for the final integration, and requested automatic switching among teammate-owned API keys.

Both AI content and the device assistant support Gemini. Generated text shares the Bedrock prompts, schema checks, prop validation and language guardrails. The assistant uses the same MCP tools, speaker context, trace and three-round limit. A model failure after a successful state change returns the existing tool result instead of repeating the action offline.

Keys are server-only: `GEMINI_API_KEYS` is a comma-separated pool; `GEMINI_API_KEY` supports a single key. The shared process-local pool selects the current healthy key, fails over once per eligible key on authentication/rate-limit/server/network failures, respects Retry-After and cooldowns, and stops when all are unavailable. Invalid model/request errors fail immediately. No key or upstream response body enters logs. No infinite retries or background quota polling.

Root `.env` loads at server startup with shell variables taking precedence. A blank ignored `.env` is the place for local credentials. Defaults remain fallback/offline. Documentation provides Gemini setup, multiple-key setup, model override and Bedrock switching. No paid live API call without configured credentials.
