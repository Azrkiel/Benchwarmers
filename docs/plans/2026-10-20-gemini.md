# Gemini implementation plan

Goal: run generated game content and assistant tool calls through Gemini with automatic key failover, preserving Bedrock and offline modes.

Architecture: a native-fetch Gemini transport owns a bounded key pool shared by content and assistant calls. A transport-independent generated-content provider shares prompts and validation; a separate Gemini assistant loop preserves native response parts and thought signatures. Native Node environment loading reads root `.env` without exposing credentials to the web bundle.

Tech: Node 22, TypeScript, Express, Zod, Vitest, Gemini REST generateContent.

```text
ignored .env -> server env -> shared Gemini key pool -> Google generateContent
                                  | 429/5xx/auth/network
                                  +-> cooldown + next eligible key (bounded)
                                  | all unavailable / invalid request
                                  +-> content templates / offline assistant

game event -> generated provider -> JSON validation -> store -> TV
assistant text -> Gemini functionCall -> MCP -> functionResponse -> reply
                                           | completed mutation + model failure
                                           +-> existing result (never re-plan)
AI_MODE/ASSISTANT_MODE=bedrock -> existing AWS callers
```
